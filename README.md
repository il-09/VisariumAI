# VisariumAI

Локальный MVP интеллектуального помощника по внутренним регламентам и документам. Интерфейс основан на приложенном HTML-прототипе; серверная часть написана на Go.

## Что реализовано

- Чат в веб-интерфейсе, который обращается к Go API (`POST /api/chat`).
- Локальный поиск по подготовленным фрагментам Инструкции по ДОУ, Матрицы обязательного визирования, Методических рекомендаций и модулей документов.
- Ответы с указанием источников; при недостатке подтверждений помощник явно сообщает об этом.
- API для списка источников (`GET /api/knowledge`), шаблонов (`GET /api/templates`) и предварительной проверки DOCX/TXT (`POST /api/check`).
- Сохранение внешнего вида, адаптивности, светлой/тёмной темы и основных разделов приложенного фронтенд-прототипа.
- Базовые HTTP security headers и лимиты на размер входящих запросов.

## Запуск

Требуется Go 1.22 или новее.

```bash
go run .
```

Откройте `http://localhost:8080`. Сервер отдаёт сайт и API на одном origin. Чтобы сменить адрес:

```bash
VISARIUM_ADDR=127.0.0.1:8090 go run .
```

Сборка бинарного файла:

```bash
go build -o visariumai .
./visariumai
```

Проверка доступности:

```bash
curl http://localhost:8080/api/health
```

## API

- `GET /api/health` — состояние сервиса.
- `POST /api/chat` — JSON `{"message":"Кто визирует приказ о вводе ИС?"}`.
- `GET /api/knowledge` — фрагменты базы знаний и источники.
- `GET /api/templates` — доступные типы модульных документов.
- `POST /api/check` — multipart/form-data, поле `file`, форматы DOCX и TXT, до 12 МБ.

## Важные ограничения MVP

Это не подключённая к внешней LLM система: ответы формируются локальным поиском и проверенными сценариями, чтобы не отправлять внутренние материалы внешнему поставщику и не выдавать неподтверждённые ответы за факты. Поиск пока лексический, не семантический; проверка документа выполняет только базовые текстовые проверки. Результат не заменяет проверку ответственным специалистом, полную сверку с актуальной редакцией инструкции и официальным маршрутом согласования.

Для production-внедрения нужны аутентификация и ролевая авторизация на сервере, журналирование без чувствительных данных, управление версиями источников, полноценный индекс (например, PostgreSQL + полнотекстовый поиск/векторное хранилище), антивирусная проверка загрузок, контроль доступа к документам и тестирование в корпоративном контуре. Не выставляйте демонстрационный сервер в публичную сеть без этих мер.

## Структура

- `main.go` — HTTP-сервер и API на Go.
- `web/index.html` — фронтенд на основе предоставленного прототипа.
- `knowledge/knowledge.json` — локальные индексируемые выдержки с цитируемыми названиями источников.
- `docs/` — приложенные справочные материалы для разработчика.
